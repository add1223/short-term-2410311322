# ADR-003: 检索 top_k 设为 5 而非 3

- 状态: Accepted
- 日期: 2026-08-20

## 背景(Context)

检索召回数量影响回答质量与上下文长度。spike 用同一段落切块(7 chunk)做了对照。

## 候选方案(Options considered)

1. **top_k=3**: 上下文短、生成快;但 spike 中相关问题"红绿循环是什么"未召回真正定义该循环的 [片段1](score 0.8274,排第 6),严格模型因此返回"未找到相关内容"。
2. **top_k=5**: 多召回 2 片段,把 [片段1] 纳入,模型正确回答并标注引用 [片段1];最坏 5*200=1000 字,远低于 num_ctx 4096。
3. **top_k=7(全量)**: 召回最全,但稀释相关信号、增生成成本。

## 决策(Decision)

选 2 top_k=5。理由:
- spike 直接证据:3 召回失败、5 召回成功且引用正确。
- 成本可控,上下文不超限。
- 配合 SCORE_THRESHOLD=0.6 双重判定,低分片段即便被召回也会被 has_answer=false 过滤。

## 后果(Consequences)

- 正面: 召回率提升,关键定义片段不被漏。
- 负面: 生成 prompt 略长、耗时略增。
- 可调: 暴露为 DOCQA_TOP_K 环境变量,W3/W4 可按 UAT 结果再调。

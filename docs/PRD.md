# AI Doc QA Assistant PRD v1 - solo-2410311322-ai-doc-qa-assistant

## 一句话产品说明

AI Doc QA Assistant 是一个本地文档问答助手:用户上传一篇文本文档,系统切块并做向量化索引;用户提问后,系统检索最相关的片段,交给本地大模型生成带来源引用的回答。核心 AI 能力是 RAG(检索增强生成)。

## 目标用户与使用场景

### 目标用户

- **学生 2410311322**:需要快速从长篇课程笔记/讲义中找到答案的学习者。
- **研究者**:希望对自己的 markdown 笔记做基于内容的问答,而不是全文逐行翻找。
- **知识工作者**:手上有一份文档,想用问答方式提取关键信息而非通读。

### 使用场景

1. editor 上传一篇 .txt/.md 文档,系统返回 doc_id,内部完成切块与 embedding 索引。
2. editor 或 viewer 针对该文档提问,例如"第三章讲了什么"。
3. 系统检索与问题最相关的 top-k 片段,拼入 prompt 交给 Ollama 生成回答。
4. 回答附带引用片段编号与原文,无相关内容时明确返回"未找到相关内容"而不是编造。

## 用户故事与优先级

| 编号 | 故事 | 优先级 |
|---|---|---|
| US-1 | 作为 editor,上传一篇文本文档,系统完成切块+索引并返回 doc_id | M（必须） |
| US-2 | 作为 editor/viewer,对已上传文档提问,获得带来源引用的回答 | M（必须） |

## 产品范围

### M 阶段(提交期必须完成)

- US-1 文档上传 + 切块 + embedding 索引
- US-2 基于检索的问答 + 来源引用
- US-3 editor/viewer 角色鉴权
- 预置 Ollama 生成模型与 embedding 模型(不开放注册)
- 无相关内容时的拒绝回答

### L 阶段(扩展期)

- US-4 文档元信息查询
- US-5 多文档联合检索
- 文档删除与列表管理
- 回答历史记录与回看
- 流式回答

## 非目标

M 阶段明确不做:

- 不做用户注册、找回密码、复杂账号体系(固定 token)
- 不接互联网检索,只基于已上传文档内容回答
- 不做流式回答,同步返回
- 不评估回答质量打分,不对比多个模型
- 不做文档版本管理、协同编辑
- 不持久化大量历史问答(可重启丢失或简单文件持久化)
- 不处理高并发,单机单用户
- 不接入付费在线模型(使用本地 Ollama)

## 关键风险、假设和依赖

### 风险

- **embedding 模型不可用或下载慢**:可能导致索引失败。回退方案:用 Ollama embedding 模型(nomic-embed-text),或极端情况下用 TF-IDF 关键词召回。
- **Ollama 生成慢**:本地模型响应慢导致 ask 接口长时间阻塞。测试环境强制 mock。
- **文档过大超出上下文**:切块策略不当导致检索质量差或 prompt 超长。
- **检索相关性差**:chunk size 或 top-k 不合理导致答非所问。

### 假设

- 假设用户使用本地 Ollama(qwen3.5:4b 生成 + nomic-embed-text embedding)
- 假设单用户单机使用,不要求分布式部署
- 假设文档为纯文本(.txt/.md),不解析 PDF/Word
- 假设问答同步返回,不要求流式

### 依赖

- 依赖 FastAPI 框架
- 依赖 pytest 测试框架
- 依赖 Ollama 本地服务(生成 + embedding)
- 依赖 Python 向量检索库(内存实现或 numpy)
